# Rowster 0.1 — plan

Status: **validated on 2026-11-10 and carried out**. What was built and what differs from this plan is in [Outcome](#outcome) at the end. The specification is [docs/specs/0.1.md](../specs/0.1.md).

## Rules for every increment

- One branch and one pull request per increment, Conventional Commits. No push, tag, release or GitHub repository creation without explicit approval each time.
- Order inside an increment: Core and its tests → service in `AppEnvironment` (live and demo) → view → strings in French → screenshot scene.
- Done means: `make test` passes with zero warnings; new screens rendered with `make screenshots` and checked in light, dark and French; `CHANGELOG.md` updated; the PR lists the manual tests.
- A driver that proves too costly stops the work and comes back with a costed alternative. No dependency is added without approval.

## Phase A — Spikes

Throwaway code in a `Spikes/` Swift package of command-line executables, on `spike/*` branches that are never merged. Only the report `docs/spikes/0.1.md` reaches `main`. No interface work starts before the report is validated.

| Spike | What it must prove | Pass criterion | If it fails |
|---|---|---|---|
| **S1 PostgreSQL** | `SSLRequest` then TLS upgrade on one `NWConnection`; SCRAM-SHA-256; a parameterized query through the extended protocol, fetched by portal in batches; `CancelRequest` interrupting `pg_sleep` | A 1,000,000-row `generate_series` is read 1,000 rows at a time with flat memory, then cancelled, and the connection is reusable | Direct TLS (PostgreSQL 17+) only, or PostgresNIO: cost reported (transitive packages, binary size, a vendored BoringSSL) |
| **S2 MySQL** | Handshake v10; TLS upgrade; `caching_sha2_password` fast path, full path over TLS, and RSA path without TLS; `COM_QUERY` stream stopped at a limit then `KILL QUERY` and drain; `COM_STMT_PREPARE`/`EXECUTE` with a bound parameter and binary rows | Same connection reusable after the kill; MySQL 8.4 and MariaDB 11 both pass | MySQLNIO: cost reported |
| **S3 SSH** | `ssh -W` over pipes, and `ssh -N -L <unix-socket>` ; askpass through the app executable; PostgreSQL TLS through the tunnel; three connections with one authentication; clean teardown when the window closes or ssh dies | A decision between `-W` and `-L` with measurements: prompts shown, connect time, failure reporting | Keep `-W` and document "no database TLS through a tunnel" as a 0.1 limit |
| **S4 Grid** | `NSTableView` with 100,000 rows × 30 columns, view reuse, fixed row height, wrapped in SwiftUI; and the same view rendered offscreen by the screenshot tool | Cell provision under 1 ms on average, no hitch visible when flinging (checked by hand), offscreen PNG is correct | Cell-based drawing or a custom layer-backed row view |

**Needed from you before the spikes** (nothing is installed today: no PostgreSQL, MySQL or MariaDB server on this Mac):

- approval to run `brew install postgresql@17 mysql mariadb` and to start them on localhost, or do it yourself. MySQL and MariaDB both want port 3306: one of them gets another port.
- S3 uses a throwaway `sshd` started as your user on a high port with a temporary key. It needs no system setting and no Remote Login. A real bastion with 1Password is a manual test for you.

## Risks

| Risk | Seen in | Mitigation |
|---|---|---|
| TLS upgrade not workable on Network.framework | S1, S2 | Spike first; costed fallback |
| MySQL binary protocol larger than expected | S2, D3 | Parameters sent as strings; decode only the types the grid displays, the rest as text |
| `ssh -W` cannot carry database TLS or avoid repeated prompts | S3 | `-L` Unix-socket forward |
| `NSTableView` not rendered by the offscreen screenshot tool | S4 | Dedicated bitmap path for AppKit-backed scenes |
| Keychain prompts after each ad hoc build | 3 | Documented; in-memory store for tests and demo; signing decision is yours |
| Classifier misses a write form | 1, 8 | Server-side read-only is the first layer; unknown statements fail closed in read-only |
| 0.1 is large (20 increments) | — | Slip order if needed: 13, then D5, then 11 |

## Outcome

Every increment was built and merged except **13 (editor completion)**, which slips to 0.2 as planned. Increments 11, 12 and D5 share one branch.

Differences from the specification, all on the cautious side:

- **Load More** in the editor runs the statement again with a higher limit instead of resuming a cursor, and only for a read. A resumed cursor would hold the connection of the window while a result tab stays open.
- **Tabs are not restored** when a window reopens. Sort order and column widths are.
- **Editing in the row inspector** is not there: the inspector shows values; edits are made in the grid. A value with several lines can therefore not be edited yet.
- **Importing and exporting the list of connections** has no button yet. The stored file never contains a password.
- **⌘W** closes the window; closing a tab is ⇧⌘W or the tab's close button.
- **Export** is available on a data tab (every row matching the filter). Editor results are copied, not exported.
- **MariaDB `ed25519`, MySQL `sha256_password`, TLS client certificates, SCRAM channel binding**: not supported, as the specification says.

Not verified by a machine, to check by hand: see [docs/manual-tests/0.1.md](../manual-tests/0.1.md).
