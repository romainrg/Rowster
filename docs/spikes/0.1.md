# Rowster 0.1 — spike report

Date: 2026-11-10. Machine: Apple Silicon, macOS 27.0.1, Swift 6.4.2, Debug builds. Servers on localhost started by `scripts/integration-servers.sh`: PostgreSQL 17.11, MySQL 26.10.0, OpenSSH 10.3 (`sshd` as the current user). The code is on the `spike/0.1` branch (`Spikes/`), which is never merged.

**Outcome: the four spikes pass. No third-party dependency is needed.** Decisions taken from the results are at the end.

## S1 — PostgreSQL

| Point | Result |
|---|---|
| `SSLRequest` then TLS on the same `NWConnection` | Works. A `NWProtocolFramer` writes the request in clear, reads the one-byte answer, calls `prependApplicationProtocol(options:)` with TLS options, then passes everything through |
| SCRAM-SHA-256 | Works, server signature verified (PBKDF2 from CommonCrypto, HMAC from CryptoKit) |
| Extended protocol, portal read in batches | 200,000 rows read 1,000 at a time (`Execute` with a row count, then `Flush`), then `Close` + `Sync`. Resident memory 10.4 MB → 16.2 MB peak, flat across batches |
| `CancelRequest` | `pg_sleep(30)` interrupted after 1.07 s with SQLSTATE `57014`; the connection ran `SELECT 1` afterwards |

Notes for the driver: `Flush` (not `Sync`) between batches keeps the unnamed portal alive; whether TLS was negotiated is read from the connection metadata after it is ready.

## S2 — MySQL

| Point | Result |
|---|---|
| Handshake v10, then TLS | Works with a framer that reads the server greeting in clear, sends the `SSLRequest` packet, then prepends TLS. The greeting reaches the driver through an object placed in the framer options |
| `caching_sha2_password` | Fast path, full authentication over TLS, and full authentication without TLS (server RSA key, OAEP through Security.framework) all work |
| `COM_QUERY` stopped at a limit | 1,000 rows read, `KILL QUERY` sent from a second connection, 11,166 buffered rows drained, the result ended with error 1317, total cost of stopping about 10 ms. The connection ran `SELECT 1` afterwards |
| Prepared statement | `COM_STMT_PREPARE` / `COM_STMT_EXECUTE` with four parameters sent as strings; binary rows decoded for strings, integers, doubles, `DATETIME(6)` and `DECIMAL`. A value containing `'; DROP TABLE x; --` came back unchanged |

Notes for the driver: this MySQL version has no `mysql_native_password` plugin and no `MD5()` function, so the native scramble is covered by unit vectors and by MariaDB; after a `KILL QUERY` the driver runs one harmless statement to absorb a late kill.

Not covered by the spike: MariaDB (installed afterwards; covered by the integration tests of the driver increment).

## S3 — SSH tunnel

One `ssh -N -L <unix-socket>:host:port` process, the socket in a private `0700` temporary directory.

| Point | Result |
|---|---|
| Tunnel ready | 0.94 s, detected by the socket appearing |
| Prompts | The passphrase prompt of a protected key arrived through `SSH_ASKPASS` with `SSH_ASKPASS_REQUIRE=force` |
| PostgreSQL TLS through the tunnel | Works: the S1 program ran unchanged against the socket (TLS, SCRAM, batches, cancel) |
| Several connections, one authentication | The main connection and the cancel connection both went through the same `ssh` process |
| Teardown | The process exits on `SIGTERM`; the socket file stays and is removed with its directory |
| Unreachable target | The forward is accepted and the failure shows at connection time; `ssh` writes `channel 1: open failed: connect failed: Connection refused` on stderr, which the app must capture to explain the error |

`ssh -W` was not pursued: it gives pipes, and the TLS upgrade that S1 and S2 rely on needs an `NWConnection`.

Notes for the tunnel: a Unix socket path is limited to 104 bytes, so the directory name must stay short; `ssh` prints a harmless `setsockopt TCP_NODELAY` line per channel on stderr.

## S4 — Grid

View-based `NSTableView`, 100,000 rows × 30 columns, fixed row height, wrapped in `NSViewRepresentable`, in an offscreen window.

| Point | Result |
|---|---|
| Cell provision | 0.003 ms per cell on average over 395,970 cells (target: under 1 ms) |
| View reuse | 960 live cell views whatever the scroll position |
| Full-page replacement | 22.7 ms per frame on average when every visible cell changes at once (jumps of 250 rows), worst 113 ms on the first one. Ordinary scrolling replaces one or two rows per frame |
| Offscreen rendering | `cacheDisplay` renders the table correctly, so the screenshot tool works unchanged |

To check by hand in the app: flinging through 100,000 rows. If it hitches, the cells move from Auto Layout to frame-based layout, which is already the plan for the real grid.

## Decisions

1. **Native drivers on Network.framework are kept** for PostgreSQL and MySQL. No fallback to PostgresNIO or MySQLNIO.
2. **MySQL uses prepared statements for generated SQL** (spec Q1), the text protocol for what the user types.
3. **SSH tunnel: one `ssh -N -L` Unix-socket forward per window** (spec Q2), not `ssh -W`.
4. **Grid: view-based `NSTableView`** with frame-based cells.
