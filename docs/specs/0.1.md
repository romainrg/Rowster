# Rowster 0.1 — specification

Status: **draft, awaiting validation**. Nothing here is implemented yet. The implementation order is in [docs/plans/0.1.md](../plans/0.1.md).

## 1. Goal

Rowster 0.1 is a native macOS database client for PostgreSQL, MySQL/MariaDB and SQLite that a developer can use daily to browse, filter, edit and query data, with three promises that hold from the first version:

- **No write without seeing the SQL.** Grid edits stay pending until previewed and committed in one transaction.
- **Production is read-only until unlocked**, and visibly production everywhere.
- **Results are bounded and cancellable.**

No tab, window or filter limits. No third-party dependency. English and French.

### In scope

| Area | 0.1 content |
|---|---|
| Engines | PostgreSQL (and wire-compatible: CockroachDB, Redshift, YugabyteDB, Supabase, best effort), MySQL and MariaDB, SQLite |
| Transport | TCP, TLS, Unix-domain socket, SSH tunnel through the system OpenSSH |
| Secrets | Keychain, or ask on every connection |
| Welcome window | Connections, groups, colors, environment labels, search, URL paste, Test |
| Work window | Sidebar, tabs, database switch |
| Data | Grid, paging, memorized multi-column sort, filter bar, row inspector, lazy BLOBs, copy as CSV/JSON/Markdown/`INSERT` |
| Writes | Pending changes, SQL preview (⌘⇧P), commit (⌘S), read-only production, destructive-statement confirmation |
| Editor | Highlighting, run current (⌘↩) / all (⌘⇧↩), one result tab per statement, cancel, history with search |
| Structure | Columns, indexes, constraints, DDL — read-only |
| Export | CSV and JSON |
| Other | Demo mode, automatic reconnection (§8.4), English and French |

### Out of scope for 0.1

Redis, MCP server, saved queries, ⌘P, CSV import, process list, visual `EXPLAIN` (0.2). Assistant panel, structure editing, ClickHouse, libSQL, D1, SQL Server (0.3). MongoDB, DuckDB, ER diagram, backup and restore (later, to be decided).

Features of the brief that were assigned to no version are placed in §13.

## 2. User journeys

1. **First connection.** Open Rowster → welcome window → New connection → paste `postgres://user:pw@host:5432/db?sslmode=require` → the form fills, the password goes to the password field only → pick the label *staging* → Test → Save → double-click → the work window opens.
2. **Browse and filter.** Click a table → the first 300 rows appear, sorted by primary key → add a filter `status = 'failed'` → click a column header, then ⇧-click another → the sort is restored next time the table is opened.
3. **Edit safely.** Double-click a cell, change it; delete a row; add a row → the three changes are highlighted and nothing has been sent → ⌘⇧P shows the exact parameterized SQL → ⌘S runs it in one transaction → on an error everything is rolled back and the changes stay pending.
4. **Query.** New query tab → type three statements → ⌘↩ runs the one under the cursor, ⌘⇧↩ runs all → one result tab each → a long one is cancelled with the Cancel button → it appears in the history.
5. **Production.** Open a connection labelled *production* → the title bar and tabs are red, a lock is shown → editing a cell is refused with an explanation → Unlock writing → confirmation (or Touch ID) → writes are possible until the window closes.
6. **Bastion.** A connection with an SSH host alias from `~/.ssh/config` (ProxyJump, 1Password agent) → the passphrase or host-key question appears in a Rowster dialog → the database connection goes through the tunnel.
7. **Demo.** `Rowster --demo` → sample connections and data, no network, no disk, no Keychain.

## 3. Screens

### 3.1 Welcome window

- Left: app name, version, New connection, New group, Import/Export connections (export never includes passwords in 0.1, see §13 Q9).
- Right: searchable list of connections, in collapsible groups. Each row: engine icon in its engine tint, name, `host:port/database` or file path, environment badge (*local*, *dev*, *staging*, *production*, or none) in the connection color.
- Double-click or ↩ connects. Context menu: Connect, Edit, Duplicate, Copy as URL (without password), Delete.
- **Connection form** (sheet): name, engine, label, color (defaults from the label, production is always red), group; host, port, user, password (*Save in Keychain* / *Ask every time*), database; or Unix socket path; or SQLite file (picker and drag and drop); TLS mode and optional CA file; *Open read-only* (forced on for production); SSH section (enable, host or alias, port, user, optional identity file — everything else comes from `~/.ssh/config`); bootstrap SQL (statements the user wants run after connecting).
- **URL paste.** Pasting a `postgres://`, `postgresql://`, `mysql://`, `mariadb://` or `sqlite://` URL anywhere in the form fills it. Unknown query parameters are listed, not silently dropped.
- **Test** opens a connection (and tunnel), runs the engine's version query, closes, and reports the server version or the error. It does not run the bootstrap SQL.

### 3.2 Work window (one per connection)

- **Title bar**: connection name, environment badge, database switcher (⌘K), read-only lock / *Unlock writing*, transaction indicator when the session is inside a user transaction, activity spinner with **Cancel**.
- **Environment tint**: the connection color tints the title bar and the tab bar. Production additionally shows a permanent *PRODUCTION* badge.
- **Sidebar**: schemas (PostgreSQL) → Tables, Views, Functions; search field filtering by name; refresh. Loaded on open through introspection only.
- **Tabs** (custom tab bar inside the window): a table tab opened by single click is a *preview* tab (italic title) and is replaced by the next single click; it becomes permanent on double-click or as soon as it has a filter, a sort change, or a pending change. An empty query tab is likewise reused.
- Tab kinds: **Data**, **Structure** (toggle at the bottom of a table tab), **Query**.

### 3.3 Data tab

- **Grid** (`NSTableView`): column header with name and type, sort indicators with order number, resizable and reorderable columns, `NULL` rendered distinctly from an empty string, long values truncated in the cell, BLOBs shown as their size.
- **Footer**: rows `1–300`, estimated total prefixed with `~` (exact count only on request), previous/next page, page size, pending-changes counter with *Preview SQL* and *Commit* / *Discard*.
- **Filter bar** (⌘F): rows of *column · operator · value*, a single *Match all / any* choice (§13 Q5), enable/disable per row, *Show SQL*, and a *raw `WHERE`* row for hand-written conditions. Operators: `=`, `≠`, `<`, `≤`, `>`, `≥`, contains, starts with, ends with, `IN`, `BETWEEN`, is null, is not null. *Any column* contains.
- **Sort**: click, ⇧-click to add a column; stored per table.
- **Foreign keys**: a small arrow in FK cells opens the referenced table filtered on the key; hovering it shows the referenced row in a popover (one bounded query on the auxiliary connection).
- **Row inspector** (right, ⌘⌥I): form view of the selected row with types; JSON tree for JSON/JSONB/valid JSON text; BLOB viewer (hex, or image when the bytes are a known image type) loading on demand; edits made here are the same pending changes as grid edits.
- **Copy**: cells or rows as TSV (default), CSV, JSON, Markdown, `INSERT` statements.
- **Editing**: double-click to edit, *Set NULL*, *Set default*, add row, duplicate row, delete rows. Modified cells, new rows and deleted rows have three distinct highlights. Tables without a usable row identity (§6.3) are not editable and say why.

### 3.4 Query tab

- **Editor** (`NSTextView`, TextKit 2): dialect-aware highlighting, line numbers, current-statement highlight, find.
- **Run**: ⌘↩ current statement (or the selection), ⌘⇧↩ all. Statements run in order and stop at the first error. One result tab per statement: grid for rows, `n rows affected` and duration for the others, error with position when the server gives one.
- **Limit**: at most *N* rows are fetched (default 1,000, configurable); *Load more* fetches the next batch when the engine allows it (§7).
- Result grids are read-only in 0.1.
- **History**: per connection, searchable, statement + date + duration + outcome, never results. Click to insert.

### 3.5 Structure tab

Columns (name, type, nullable, default, key), indexes, constraints (primary, unique, foreign, check), and the DDL. For PostgreSQL the DDL is reconstructed from the catalogs and labelled as reconstructed.

### 3.6 Dialogs

- **SQL preview** (⌘⇧P): the statements of the pending change set, with parameters shown both as placeholders and inlined for reading. Copy, Commit, Close.
- **Destructive confirmation**: the full statement(s), the connection name and environment, a default button that is *Cancel*.
- **Unlock writing**: explains that the unlock lasts until the window closes; Touch ID when enabled in Settings.
- **SSH prompt**: passphrase, password, host-key confirmation, as asked by OpenSSH.

### 3.7 Settings

Default page size and editor limit; Touch ID for unlocking; history on/off and clear; appearance of `NULL`; language follows the system.

## 5. Safety design

### 5.1 Read-only

Session-level read-only is advisory on PostgreSQL and MySQL: a user can type `SET TRANSACTION READ WRITE`. Rowster therefore applies **two layers** on every connection of a read-only window, including after a reconnection:

1. **Server side**, right after authentication and before the bootstrap SQL:
   - PostgreSQL: `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`
   - MySQL/MariaDB: `SET SESSION TRANSACTION READ ONLY`
   - SQLite: the file is opened with `SQLITE_OPEN_READONLY`, plus `PRAGMA query_only = ON`
   
   If this statement fails, the connection is closed: it fails closed.
2. **Client side**: `StatementClassifier` rejects, before any round trip, every statement that is a write, that it cannot classify, or that would lift the server-side setting (`SET … READ WRITE`, `SET default_transaction_read_only`, `BEGIN READ WRITE`, `RESET ALL`, `PRAGMA query_only`, …). The message offers *Unlock writing*.

For SQLite the classifier is replaced by the exact answer of `sqlite3_stmt_readonly`.

**Unlocking** needs a confirmation (or Touch ID), applies to the window only, is shown in the title bar, can be re-locked, and ends when the window closes. On unlock the server-side setting is reverted and SQLite is reopened read-write.

**Known limits, to document in `SECURITY.md`:** a read-only transaction does not stop side effects that are not table writes (`pg_terminate_backend`, `nextval`, `COPY … TO PROGRAM` for superusers). The classifier guards against accidents; it is not a security boundary against the person at the keyboard. The strong guarantee remains a database role without write privileges.

### 5.2 Destructive statements

The classifier tokenizes with the dialect (comments, strings, dollar-quoting) and flags: `DROP …`, `TRUNCATE …`, `ALTER … DROP …`, and `DELETE`/`UPDATE` with no top-level `WHERE`, including behind a `WITH` prefix. With *Run all*, one dialog lists every flagged statement before anything runs. Opaque statements (`DO`, `CALL`, `EXECUTE`) are treated as writes; they are not confirmed as destructive (§13 Q6).

### 5.3 Nothing runs by itself

On open: authentication, read-only setup, bootstrap SQL written by the user, introspection. Nothing else. Tabs are restored but not re-run: a restored query tab shows its text, a restored table tab reloads its first page only when it is displayed. No automatic `COUNT(*)`.

## 6. Core design (`RowsterCore`)

`RowsterCore` imports Foundation, Network, CryptoKit, CommonCrypto, Security, SQLite3 and os. Never SwiftUI or AppKit.

### 6.1 Protocols

```swift
public protocol DatabaseDriver: Sendable {
    var dialect: any SQLDialect { get }
    func connect() async throws
    func close() async
    func execute(_ sql: String, parameters: [SQLValue], batchSize: Int) async throws -> any ResultCursor
    func cancelCurrent() async          // safe to call from another task at any time
    func introspector() -> any SchemaIntrospecting
}

public protocol ResultCursor: Sendable {
    var columns: [ColumnInfo] { get }
    func next() async throws -> [Row]?  // nil when exhausted; pull-based, so memory is bounded
    func close() async throws           // releases the portal / kills the rest of the result
    var rowsAffected: Int? { get }
}

public protocol SQLDialect: Sendable {
    func quote(identifier: String) -> String
    func placeholder(at index: Int) -> String          // $1, ?, ?1
    func paginate(_ select: String, limit: Int, offset: Int) -> String
    var readOnlyStatements: [String] { get }
    var readWriteStatements: [String] { get }
    func tokenizer() -> SQLTokenizer
}
```

Transactions are plain statements issued by `CommitRunner`, which also tracks the transaction status the server reports. The pull-based cursor replaces an `AsyncSequence` on purpose: it gives back-pressure for exports and makes "stop at the limit" explicit.

### 6.2 Other Core modules

| Module | Role |
|---|---|
| `Values/` | `SQLValue` (`null`, `text`, `integer`, `double`, `bool`, `bytes`, `deferredBytes(length)`), `ColumnInfo`, `Row` |
| `SQL/` | `SQLTokenizer`, `StatementSplitter` (comments, strings, dollar-quoting, `DELIMITER`), `StatementClassifier`, the three dialects |
| `Builders/` | `FilterBuilder`, `BrowseQuery` (projection, sort, paging, BLOB deferral), `ChangeSet`, `CommitRunner` |
| `Drivers/SQLite/` | Driver on `SQLite3` |
| `Drivers/Postgres/` | Message codec, SCRAM-SHA-256, MD5, startup, extended query, `CancelRequest`, introspection queries |
| `Drivers/MySQL/` | Packet codec, handshake v10, `caching_sha2_password`, `mysql_native_password`, text and prepared-statement protocols, introspection queries |
| `Transport/` | `ByteStream` protocol, Network.framework implementation with TLS upgrade, `TransportFactory` |
| `SSH/` | `SSHTunnel` (process supervision), askpass protocol |
| `Connections/` | `ConnectionProfile`, `ConnectionStore` (JSON), `ConnectionURL`, `SecretStore` (Keychain and in-memory) |
| `Session/` | `Session` actor: primary and auxiliary connections, read-only state, reconnection |
| `Export/` | CSV and JSON writers, clipboard formatters |
| `History/` | Query history store |
| `Support/` | `L(...)`, logging wrapper |

### 6.3 `ChangeSet`

- Row identity: the primary key; otherwise a unique index whose columns are all `NOT NULL`; for SQLite rowid tables, the `rowid`. With none of these the table is read-only in the grid.
- `UPDATE t SET c = $1 WHERE pk = $2`, `DELETE FROM t WHERE pk = $1`, `INSERT INTO t (cols) VALUES (…)`. Columns left untouched in a new row are omitted so defaults apply.
- Order inside the transaction: deletes, updates, inserts.
- Each `UPDATE` and `DELETE` must affect exactly one row, or everything is rolled back with a message naming the row.
- If the session is already inside a transaction the user opened in the editor, commit is refused with an explanation.

### 6.4 `FilterBuilder`

Produces `WHERE` text with placeholders plus the parameter list. Contains/starts/ends escape `%` and `_` and add an `ESCAPE` clause. Non-text columns are cast for text operators. Case-insensitive match uses `ILIKE` on PostgreSQL and the column collation elsewhere. The raw `WHERE` row is user-written SQL, shown as such, and passed through the classifier.

## 7. Engines

| | PostgreSQL | MySQL / MariaDB | SQLite |
|---|---|---|---|
| Auth | SCRAM-SHA-256, MD5, cleartext (TLS only), trust | `caching_sha2_password` (fast path; full path over TLS, or RSA-OAEP via Security.framework without TLS), `mysql_native_password`, auth switch | — |
| TLS | `SSLRequest` then upgrade | Capability flag then upgrade | — |
| User SQL | Extended protocol, one statement per `Parse` | `COM_QUERY` (text protocol) | `sqlite3_prepare_v2` |
| App SQL with parameters | Extended protocol | `COM_STMT_PREPARE` / `COM_STMT_EXECUTE` (binary protocol) | `sqlite3_bind_*` |
| Row limit | `Execute` with a row count on the portal; *Load more* resumes it | Read *N* rows, then `KILL QUERY` from a second connection and drain; no *Load more* | Stop stepping; *Load more* continues |
| Cancel | `CancelRequest` on a new connection | `KILL QUERY <id>` on a second connection | `sqlite3_interrupt` |
| Database switch | New connection | `USE` | — |
| Estimated count | `pg_class.reltuples` | `information_schema.TABLES.TABLE_ROWS` | exact, on request only |
| DDL | Reconstructed from catalogs | `SHOW CREATE TABLE` | `sqlite_master.sql` |

**Deviation from the brief, to validate (§13 Q1).** The brief gives MySQL the text protocol. The text protocol has no bound parameters, so invariant 5 cannot hold for filters and grid edits with it. This spec uses prepared statements for everything Rowster generates and keeps the text protocol for what the user types. The cost is a binary-row decoder in the MySQL driver.

**Not in 0.1:** SCRAM channel binding, GSS/Kerberos, client certificates (§13 Q8), MariaDB `ed25519` auth, MySQL `sha256_password`, PostgreSQL `COPY`.

**BLOBs.** In the Data tab Rowster writes the `SELECT`, so binary columns are projected as their length and fetched by primary key when the inspector asks. In the editor the user wrote the query, so the bytes arrive; cells are capped for display only.

## 8. Connections and sessions

### 8.1 Storage

- `~/Library/Application Support/Rowster/connections.json`: profiles and groups, no secret field in the type.
- Keychain: one generic password per connection, service `io.github.romainrg.Rowster`, account = connection UUID.
- `~/Library/Application Support/Rowster/state/<uuid>.json`: per-table sort and column widths, open tabs.
- `~/Library/Application Support/Rowster/history.sqlite`: query history, file mode 0600.

### 8.2 Session model

Each work window owns a `Session` with:

- a **primary connection**: everything the user runs (editor, commits, table pages). Session state such as temporary tables and `SET` is therefore consistent. Requests are serialized.
- an **auxiliary connection**, opened lazily: introspection, FK hover previews, estimated counts. A long user query never blocks the sidebar.
- short-lived connections for cancel (`CancelRequest`, `KILL QUERY`).

Read-only setup and bootstrap SQL apply to the primary connection; read-only setup applies to the auxiliary one too.

### 8.3 SSH tunnel

`/usr/bin/ssh` does everything SSH: `~/.ssh/config`, agents, ProxyJump, known hosts. Rowster passes the host (or alias), and only the options the user filled in. Prompts come through `SSH_ASKPASS` with `SSH_ASKPASS_REQUIRE=force`: the askpass program is the Rowster executable itself started in a helper mode, which forwards the question to the running app over a private Unix socket and prints the answer. No second binary to sign. Answers are never stored or logged.

The brief specifies `ssh -W host:port`. Two facts make the exact shape a spike question (§13 Q2):

1. `-W` gives a pair of pipes. Network.framework cannot run TLS over pipes, so "TLS to the database through the tunnel" (common with managed databases behind a bastion) is not reachable that way without deprecated APIs.
2. A session needs several connections (auxiliary, cancel). One `ssh -W` per connection means one authentication each, which is several Touch ID prompts with a 1Password or Secretive agent.

The candidate that solves both without a local TCP port: **one `ssh -N -L <unix-socket>:host:port` per window**, the socket living in a private `0700` temporary directory. Every database connection of the window, TLS or not, connects to that socket. The spike compares it with `-W`.

### 8.4 Reconnection

When a connection is found dead, the next action reconnects (tunnel included), re-applies the read-only state of the window and the bootstrap SQL, then runs the action if it is a read. A write is never replayed: the user is told and runs it again. If the connection dropped inside a transaction, the user is told the transaction is lost. Pending grid changes survive, since they live in the app.

### 8.5 TLS modes

*Disabled*, *Preferred* (default: try TLS, accept any certificate, fall back to clear), *Required* (no fallback, no verification), *Verify CA*, *Verify identity*, with an optional CA file. Through an SSH tunnel the name checked is the database host, not the socket.

## 9. Demo mode

`--demo` builds `AppEnvironment.demo()`: an in-memory `SecretStore`, an in-memory connection list, and a `TransportFactory` that cannot open sockets or processes. Sample connections of each engine are served by fake drivers backed by one in-memory SQLite sample database (a small shop: customers, orders, products, with a JSON column, an image BLOB, foreign keys and a table without primary key), presenting the dialect and tint of the engine they stand for. One sample connection is labelled production to show the lock. README screenshots are rendered from this environment.

## 11. Platform notes that affect the design

1. **Keychain and ad hoc signing (§13 Q3).** An ad hoc signature has no stable identity: the Keychain ties each item to the exact build that created it. After every update of Rowster, macOS will ask the user to allow access again for each saved password. Avoiding this needs a stable signing identity, which is a signing change under invariant 8.
2. **Local Network privacy.** Since macOS 15, connecting to a host on the local network shows a system permission prompt, sandboxed or not. Rowster needs `NSLocalNetworkUsageDescription` in `Info.plist` (a usage string, not an entitlement), in both languages. Loopback is exempt.
3. **TLS upgrade.** Both wire protocols start in clear and switch to TLS mid-stream. Network.framework has no direct call for that; the expected route is a framer that prepends TLS after the clear-text exchange. This is the first thing the PostgreSQL spike proves.
4. **No UI automation, no permission prompts in tests.** Tests never touch the real Keychain, Touch ID, or the local network.

## 12. Testing

- **Core unit tests**: codecs from captured byte sequences (PostgreSQL, MySQL); SCRAM vectors of RFC 7677; `caching_sha2_password` scramble; `StatementSplitter`; `StatementClassifier`; `FilterBuilder` and `ChangeSet` in each dialect with hostile names (`"`, `` ` ``, `]`, spaces, emoji, reserved words) and hostile values; read-only policy; URL parsing; connection store has no secret.
- **SQLite** always tested for real, in process: driver, cursor, `CommitRunner` rollback, read-only.
- **Integration** (`make integration`, never in CI, never shipped): PostgreSQL and MySQL installed with Homebrew on localhost, an SSH tunnel against a throwaway user-level `sshd` on a high port with a temporary key. Skipped with a clear message when a server is missing.
- **Screens**: each screen is a scene of the screenshot tool, rendered in light, dark and French from the demo environment.
- **Manual**: each increment's PR lists the manual steps (Keychain prompt, Touch ID, real bastion, 100,000-row scroll).
